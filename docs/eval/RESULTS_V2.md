## Metric plan (written 2026-11-13 BEFORE any held-out prediction was computed; unchanged after)

This section is fixed: `python -m proveflow.eval.heldout` verifies its sha256 before computing
anything and copies it here byte-for-byte. Everything after the "Generated results" heading is
generated by that single run, except the hand-written "Limitations" section at the end.

**Data.**
- `data/eval/roles/heldout_v2/labels_heldout_v2.csv`, sha256
  `55981d7385f530bbd6d9809818dab8a347cb4cd30a8cfed91640432a8f8963bb`: 55 rows from 7 servers.
- Truth = `<role>_final` (equal to `<role>_a`; single human labeler, blind, no LLM pre-labels).
- `uncertain_a` marks rows the labeler found ambiguous.
- Tool records come from `heldout_tools.jsonl`, the same name/description/schema the labeler saw.

**Classifiers (frozen; both loaded in-process in the same run).**
- **v1:** `src/proveflow/flows/roles.py` and `server_roles.py` exactly as in git commit
  `86157de`. Expected classifier sha256
  `08deee09cb4feb3cf388b93c263dbcdc6f95165cba1678a6305680b5b60f4a16`.
- **v2:** the same two files in the working tree. Expected sha256
  `db4100d59c74668c594947fd0bf7d52869bfc831778ff24ac2de352f91a78a50`.
- The sha256 is the one `proveflow.eval.metrics` uses: for each file, its name then its bytes.
  Both shas are asserted before any prediction. A mismatch aborts the run, and the counter is
  not touched.
- Prediction: `classify_tool(tool_name, server_id, description, input_schema)` then
  `assigned_roles`. Tool-level only; server-level roles are not involved.

**Metrics.**
- For each role (`untrusted_source`, `private_data`, `sink`) and each of v1 and v2: TP, FP, FN,
  TN, precision, recall and F1, always with the counts.
- **CIs:**
  - Wilson 95% CI for precision (k = TP, n = TP+FP) and recall (k = TP, n = TP+FN) whenever
    n > 0. n < 10 is flagged as "very wide".
  - Deviation from the brief, stated here in advance: **F1 has no Wilson CI.** F1 is not a
    binomial proportion, so a Wilson interval is not defined for it. F1 is reported as a point
    estimate with its counts, and no other interval method is used.
- **Primary:** all 55 rows.
- **Secondary:** only rows with `uncertain_a = no`.

**Per-rule exposure (v2 rules; C10 reverted and C11b skipped, so neither is in v2).**
- Exposure = the number of held-out tools on which the rule's trigger matches, whether or not
  it changes the final role.
- Computed by eval-only code that calls the frozen v2 module's own functions and constants;
  nothing in `src/proveflow/flows/` is edited.
- The raw (pre-threshold) evidence is rebuilt in `classify_tool`'s exact order, and the run
  asserts per tool that it yields the same selected roles as `classify_tool`.
- **Rules that add evidence** are counted by their evidence reason:
  - C1: "saves output to a file"
  - C2: "schema: repository param"
  - C3: "name: version-control write"
  - C4: "schema: agent text"
  - C8: "(GET can carry data)", i.e. an agent-controlled URL param
  - C9: "schema: 'model' + input"
  - C11a: "name: captures rendered content"
  - C11c: "description: says its output is untrusted"
  - C11d: "description: arbitrary code execution"
  - C12: "schema: HTTP header param"
- **Rules that remove v1 behaviour** are counted by their trigger:
  - C5: name tokens contain `browser` plus `hover` or `drag`, or `close` plus a UI noun.
  - C6: the name writes, has no read verb, and the description alone yields private-data
    evidence.
  - C7: name token `navigate`.
- **A rule with exposure 0 is reported as "untested", never as passing.**

**Errors.** For v1 and v2, a per-tool list of every FP and FN: role, kind, tool_name, uncertain
flag.

**Claims.** No significance tests and no claim that v2 is better than v1. n is small (55 tools,
7 servers), so the intervals are wide and are to be read as such.

**Protocol.**
- One invocation evaluates v1 and v2 together.
- It refuses unless `guard_heldout` passes and `heldout_evaluations == 0`.
- It writes `heldout_evaluations = 1` BEFORE computing or printing any result.
- Any later invocation is refused.
- The v1 test split and its counter are not read or touched.

## Limitations (hand-written after the single run; not generated)

- **Attrition: 7 of 14 selected servers were collected** (eval-collect run 43441434109).
  All 7 failures are server-caused (docs/eval/SERVERS_V2.md, "Failure classification"):
  - **missing credential:** bitbucket, perplexity
  - **needs a database configuration:** mssql-reader
  - **import error from open-ended `mcp>=1.x`** (resolves to mcp 2.x): meok-koikeeper,
    wander-agent
  - **broken publish:** glyphic (`workspace:*` dependencies), a11y-scanner (`lib/` missing
    from the tarball)
- **Missing categories:** no browser, vcs-hosting, database or web server is in the held-out
  set.
  - The remaining llm-proxy (`purmemo`) and messaging (`emailmd`) servers matched their
    category only incidentally.
  - The set is 55 tools from 7 servers; one server, pdf-suite, supplies 15 of them.
- **Single human labeler**, blind, with no LLM pre-labels. No second labeler, so there is no
  inter-rater agreement (no kappa).
- **19 of 55 rows are marked `uncertain_a = yes`.** The secondary table excludes them
  (N = 36).
- **Only 4 `untrusted_source` positives** (1 among the 36 certain rows). Source precision and
  recall are therefore not interpretable; only the counts are.
- **v2's rules were tuned on the v1 dev split only** (docs/eval/V2_CHANGELOG.md); that dev
  result is not a claim.
- **10 of the 13 v2 rules are untested here** (exposure 0): C2, C3, C4, C5, C7, C8, C9, C11a,
  C11c and C11d. Only C1 (11 tools, all pdf-suite), C6 (2: pdf-suite, purmemo) and C12 (1:
  pdf-suite) were exposed.
- **The v1→v2 differences are concentrated on one server.**
  - v2 fixed 10 v1 errors and introduced 0.
  - 8 of the 10 are `sink` false negatives on pdf-suite tools whose output-path parameter
    triggers C1.
  - The other 2 are `private_data` false positives removed by C6 (pdf-suite, purmemo).
  - The sink recall change (8/25 → 16/25) is therefore evidence about C1 on one server's
    tools, not about v2 in general.
  - `untrusted_source` is identical for v1 and v2.
- **Partial blindness of the classifier author:** while selecting servers, Claude read README
  excerpts naming a few held-out tools and parameters (SERVERS_V2.md, "Blindness during
  selection"). No rule was changed after Stage B.
- **Reproducibility:** the eval module and this plan were uncommitted at run time.
  - The run recorded `git_head` `a74bc9d` (labels commit), `eval_module_sha256` and
    `plan_sha256`. The classifier files were unchanged (both shas asserted).
  - The held-out counter is now 1, and the evaluation cannot be re-run.
