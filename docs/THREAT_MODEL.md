# Threat model v0 [planned]

> Threats **to proveflow and its user** — this tool reads secret-bearing configs and runs attack
> payloads, so it is itself an attack surface. Each threat maps to a control and a planned test.
> Status: design document; controls are implemented in the phase that builds the component.

| # | Threat | Scenario | Control | Planned test |
|---|---|---|---|---|
| T1 | Malicious MCP server runs during introspection | `tools/list` requires launching the configured server — its code executes, exactly as the user's client would run it. A malicious server could attack the machine or hang forever. | Per-server consent prompt before launch; hard timeout + process kill; `--no-launch` mode (names/descriptions only); never `tools/call` on real servers in default mode | integration: timeout kills a sleeping fake server; safety: upstream call log asserts zero `tools/call` |
| T2 | Secret leakage from client configs | Env values, headers, URL query strings, args contain API keys; they could reach logs, cassettes, reports, or LLM prompts | Redaction at read time into `RedactedValue` (type stores only sha256 prefix + length — raw value cannot be stored); structured logging only | [impl][tested] Phase 1a: env/header values always fully redacted; args/URLs by documented pattern rules (docs/REDACTION.md); Hypothesis property test plants secrets in env/headers/flag args/URL query/userinfo/Bearer and asserts none appear in terminal, JSON, SARIF or DEBUG logs; mutation test per redaction rule; error messages carry positions/field names only. **Residual:** short unflagged positional secrets in args are not caught (pinned by a test) |
| T3 | Attack payloads reach a real sink | A prove-run payload convinces the agent to call a real `send_email`/`post` tool | Sink sandbox always ON in twin mode and not disableable; sink calls answered with fake success, never forwarded | safety test: upstream call log asserts sink calls never forwarded; mutation test: disabling the sandbox makes a named test fail |
| T4 | Payload causes real-world harm even in twin | Payload contains a real exfil endpoint or format-valid card/ID numbers | Payloads target only per-trial canaries and honey values; honey formats are deliberately invalid; corpus normalization strips/replaces embedded URLs at rewrite time | unit tests on goal rewriting; corpus validation rejects format-valid PAN/ID patterns |
| T5 | Poisoned dataset | A corpus source ships records crafted to attack the *user of the dataset* (e.g. prompt-inject the normalizer or reports) | Datasets fetched at runtime with pinned revision + checksum; records treated as data everywhere (no eval/exec, no f-string templating of raw text into code); reports escape payload text | checksum-mismatch test; report-rendering test with hostile record text |
| T6 | Malicious cassette on replay | `replay` parses a user-supplied cassette file; crafted JSONL could exploit the parser or fake verdicts | Cassettes validated against pydantic models (`extra="forbid"`); hashes recorded at write time and checked at replay; replay never executes content | unit: malformed/oversized cassette rejected; determinism: same cassette ⇒ byte-identical verdict JSON |
| T7 | Supply chain (our dependencies) | A compromised dependency reads the configs we parse | Minimal dependency set (Phase 0: typer, rich, pydantic only); `uv.lock` committed; deps added only with per-phase justification | CI `uv sync --locked` fails on lock drift |
| T8 | proveflow damages the user's setup | A bug edits or corrupts a client config | proveflow never writes to client configs; fixes are separate patch files in `proveflow-fixes/` | [impl][tested] Phase 1a: configs opened `rb` only; `tests/safety/test_configs_untouched.py` asserts sha256 + mtime of every fixture config unchanged after discover/scan |
| T9 | Real flaws found in third-party servers | Publishing a confirmed exploit harms server users | Private report to maintainer first; no exploit publication before a fix window (CLAUDE.md safety rule) | process rule, not a test; checked at report-publication time |
| T10 | Secret leakage through error paths | A parse/validation error message echoes file content or input values (pydantic `input_value=...`) | JSON errors report parser message + line/column only; entry errors name fields only; `proveflow.toml` errors use `errors(include_input=False)`; Typer `pretty_exceptions_show_locals=False` | [impl][tested] Phase 1a: `test_io.py`, `test_readers.py::test_bad_entries_skipped_without_leaking`, `test_overrides.py::test_validation_error_does_not_echo_input`, `test_cli.py::test_tracebacks_never_show_locals` |
| T11 | Secrets echoed by a launched server | A server prints env to stderr or puts env values into tool descriptions | Scrub every LaunchSpec raw value from tool metadata and stderr before use | [planned] Phase 1b |
| T12 | Config changed between discover and launch (TOCTOU) | Launch would use values the user never saw | Launcher re-reads the config and compares fingerprints with the discovered `ServerSpec` | [planned] Phase 1b |
